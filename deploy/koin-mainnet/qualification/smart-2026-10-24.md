Running the installer with no arguments prints the proposal and approval hash
without service or configuration writes:

```sh
node deploy/koin-mainnet/install-smart-qualification.js
```

```sh
node deploy/koin-mainnet/install-smart-qualification.js \
  --approve 3aebefc063417e4b165f516551b7f49a5f0fbcd9eaf24d5715df3a4fcf8b2b26
```

The installer requires the running `cbdb3a5` prepaid service, exact deployment
and catalog commitments, no conflicting qualification policy, a clean checkout
with only this review's allowed files changed, and root-owned regular settings.
It takes an exclusive update lock, stores a private backup under `/root`, stops
the service cleanly, and adds only `qualificationPolicies` to the installed
`runtime.json`, retaining its owner/group/mode. All other configuration is checked
for changes. Original bootstrap plans remain immutable; the operational policy
and previous settings are retained together in the private backup.

It starts the same installed code and verifies fresh loopback/HTTPS health plus
the running qualifier through the private loopback operator endpoint. The
operator secret is never printed or sent externally. A failed health check
restores only the prior runtime settings and restarts the same code. New payment
or qualification journals are never replaced by old copies. A concurrent
configuration edit is preserved and requires inspection rather than overwrite.
No contract deployment, key generation, funding or fabricated provider record is
performed. Existing prices, purchase limits, free-model eligibility and reward
funding remain the installed values.

Keep Smart loaded in Test 206.1. Use **Settings → AI credit account** to sign in
and link the existing provider wallet, then **Earn → Share AI capacity**. Wait
for fresh signed qualification and network-confirmed ONLINE. On the buyer,
select Smart for network chat; a local Fast model is a separate selection and
