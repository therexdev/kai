# Shared workspace login

The canonical workspace is https://koinosai.com/chat and https://koinosai.com/build. Website login lands on /chat; the earlier /app#chat bookmark redirects there. Account and Dashboard links open https://credits.koinosai.com/account. Chat and Build use the same verified login. /app/history preserves earlier chats, documents and tasks with their existing account and execution model.

The website's /chat shell embeds the authenticated credit-service chat at a fixed URL while the address bar stays on koinosai.com/chat. This keeps credit credentials and requests on their issuing origin; no reusable token is exposed to the website or URL. Only this chat route allows the exact koinosai.com frame ancestor. Dashboard navigation targets the top-level page. An origin- and source-checked message returns the top-level page to login on session expiry or sign-out. The same-site subdomains retain their separate HTTP-only cookies. New conversation history remains browser-local and account-scoped; earlier server-saved chats remain accessible.

A signed-in credit account authorizes a two-minute, single-use code for the fixed https://koinosai.com/auth/workspace/callback. The website requires its own HTTP-only state cookie and server-stored S256 verifier before exchanging that code. Each Chat/Build entry checks the current central login, including when an older website session exists. A one-use, 60-second entry receipt avoids a callback redirect loop. Existing website sessions are reused when the verified identity matches. The exchange sends no browser cookie, reusable credit token, API key or wallet credential to the other host. The issuer subject maps to the existing website workspace ID when its verified email matches; new identities receive a new workspace. No financial balance, wallet identity, grant, project or chat is moved or deleted. Earlier website sessions remain separately revocable.

Device links stay with their issuing service and preserve the eight-character code format used by current Android releases. Core opens the browser with the exact prefilled URL, like Android; the manual code remains a backup. Duplicate approval by the same account succeeds; another account cannot claim it. Lost device responses recover the same session, with only hashes stored. Revocation and expiry remain enforced. Wallet-signed credit access links are handled by the companion credit service; a device login alone cannot move wallet ownership.

Deploy this website source with the companion payment-runtime update-workspace release. Until the capability check succeeds, the old routes remain in use. The Core companion change makes account selection, disconnecting and fresh-code recovery visible. Live Google consent and a real Core connection still require acceptance testing after deployment.
